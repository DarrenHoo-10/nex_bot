## 变更

- 工作区不再是窗口里的悬浮卡片：去掉外层内边距、边框、圆角和阴影，左栏和右侧资料面板顶到窗口边缘，只剩系统窗口这一层。
- 右侧资料面板的展开/收起由头部按钮改为贴在面板边缘的把手；宽窗口里面板内的图钉和关闭按钮移除，窗口宽度 1040px 以下面板为浮层，保留关闭按钮。
- 「待办」入口左对齐。
- Windows 窗口按钮高度由 64px 改为 36px，面板内容从按钮下方开始。
- 图钉按钮移除后，已置顶的联系人仍按原顺序排在前面，但界面里暂时没有取消置顶的入口。

## 限制

- 设置页、待办页和 720px 以下窄窗口没有逐页截图检查；把手的悬停动画和键盘焦点样式没有截图确认。
- Mac 和 iOS 没有重新构建，也没有做等价的原生改动：它们是原生 SwiftUI 窗口，不存在这层外框，但资料面板的开关方式与本次的把手不一致，未做一致性验证。
- 没有在真机上覆盖安装 Android，也没有用已安装的 Windows 客户端走完整更新流程。
- Windows 包没有发布者数字签名，Android 为调试签名。

## 过程说明

第一次和第二次 OSS 发布都在上传 176MB 的 EXE 时失败：Node 的 `fetch` 默认只等 5 分钟的响应头，从 Tokyo 上传到北京 OSS 超过了这个时间（上一版没有遇到）。失败发生在清单写入之前，线上清单始终是 0.9.23，没有出现半成品。
修复是把 PUT 上传改为 `node:https`（`2e0f98e9`），并用本地 HTTPS 服务器验证了 8MB 正文的 200 和 409 两种状态。重新做 dry-run（旧记录保留为 `*.attempt1.json`）后发布成功。
上传使用禁止覆盖并读回校验，重跑是安全的。

前一版 `main-52295683-20261031`、部署前备份和旧清单都保留用于回滚。
本机证据在忽略的 `release/chrome-verification/`、`release/ship-0.9.24/`、`release/deployment-single-layer/`。
