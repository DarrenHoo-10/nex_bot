# Stock history aliases and private conversation continuity

Local implementation only. No deployment, live identity, market, model or Feishu data is used by these checks.

Core resolves the Stock instance and `(issuer, subject)` through the current verified account and its binding. An active native account can renew the accepted Stock binding through its long-lived delegation even after the browser lease expires. Source requests recheck the subject after the response. Revocation, unavailable identity, a disabled/missing connector or a mismatched subject fails closed. Caller-supplied legacy session IDs are namespaced aliases, never identity or Feishu routing proof.

`GET /api/v1/finance/history?after=…&limit=…` is imported with a durable per-account/per-instance cursor. Protocol 2 uses journal `cursor`, stable original `id`, `cursorVersion:2` and `capabilities.deletions`. Edits replace their own source row, and deletion tombstones are retained even when no source content was previously imported. A cursor protocol upgrade restarts source scanning without duplicating internal messages; a downgrade is refused. Each validated page and cursor advance commit in one Core transaction. Out-of-order, repeated or malformed page cursors roll back the entire page. Source errors are retained as body-free import status and are returned by the aliases endpoint, never presented as successful empty history.

Each legacy Stock session becomes a private conversation under the stable finance assistant. Imported IDs, roles, text and source timestamps survive replays and restart. Source context keeps only the documented object references and dates. No unverified `feishu:` session name establishes a channel destination. Imported messages bypass publish callbacks, Feishu delivery and the memory retain ledger; automatic personal-memory capture skips this source class. An explicit later user request to import selected history into memory retains its existing authorization path.

Alias routes:

- `GET /api/finance/aliases`: scoped aliases plus durable import state.
- `GET /api/finance/alias?sessionId=…&before=…` (or `after`): up to 200 real, non-tombstoned messages, `hasMore`, `nextBefore`, `nextAfter`, exact conversation ID and scoped streaming. Forward pagination reads the oldest next page, preserving all middle messages beyond 200.
- `POST /api/finance/alias`: `sessionId`, `text`, `clientId`, optional initial `sourceContext` and one-turn `modelSelection` (`connectionId`, `model`, optional `reasoning`); returns the exact topic input receipt (`botId`, `conversationId`, `messageId`, nullable `taskId`, `queued`). Unknown aliases may be created on a valid first input; deleted aliases cannot be resurrected.
- `GET /api/finance/alias/context`: Stock-compatible snake_case context fields derived from the actual Pi projection and the selected model. Token counts use the same conservative estimator as the runtime; they are estimates, not provider billing. The trigger follows the runtime's actual reduction limits. Summary coverage reflects actual compaction entries, including runtime compactions.
- `POST /api/finance/alias/compact`: a real model summary through the existing tracked completion path and a real Pi compaction. It keeps four recent user turns, preserves originals, rechecks identity and projection version, and commits only if the effective context shrinks. Busy, changed, cancelled, over-window or non-shrinking work leaves the original context intact.
- `POST /api/finance/alias/delete`: hides and tombstones only the selected topic; stops its task tree, redacts its visible messages and clears only its rebuildable context/summary. Other topics and their running tasks, assistant identity, grants, business-effect audit and task receipts remain intact. This is topic removal, not a global memory-forget command.

Runtime hydration rebuilds from committed imported messages and completed owner turns. It occurs before the worker starts; a crash between page commit and projection save cannot strand missing historical context. Source edits/deletes invalidate only that conversation's old projection and working note. New input is held while its source import is incomplete. Background recovery advances bounded page batches and retries from the persisted cursor while the account session remains valid.

`POST /api/agents/cancel` now accepts optional `messageId`: a queued input is cancelled by exact receipt, and an acquired task cancels only that input's task tree. Omitting it preserves explicit whole-topic cancellation.

Verification: `stock-history.test.ts` uses temporary Core databases and synthetic source pages. It covers cursor restart/replay, account alias isolation, updates/tombstones, real worker continuation of imported context, real fake-model compaction with reduced context, topic-only removal, exact queued-input cancellation, 215-message pagination, protocol upgrade and atomic malformed-page rejection. `stock-finance.test.ts` includes real HTTP account routing and native history renewal after web lease expiry, plus upstream logout rejection. No release packages were built. Rollback must retain these additive aliases, source receipts and tombstones; restoring an older database would resurrect deleted history and lose new task effects.

## Per-input model compatibility

An explicit legacy per-turn model/reasoning choice resolves through the same owned model connection, model visibility and reasoning options as ordinary Core chat. The resolved model/connection/effort is stored on the durable input, then on the actual task, without a credential copy. The complete requested selection participates in receipt hashing. FIFO, restart and child work keep that selection; a subsequent input without an override remains automatic. The assistant default is never changed. Invalid or unavailable providers, disabled model choices and unsupported explicit reasoning fail clearly; an already accepted pinned provider that is disabled later fails the task rather than falling back to another model. `input-model.test.ts` verifies two actual Pi/fake-provider routes, real reasoning parameters, replay conflict, cancellation, restart and default preservation.
