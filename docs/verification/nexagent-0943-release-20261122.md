## 改动

- **历史分页**（电脑端 `reader.ts`）：工具调用与其结果映射为同一条显示内容，`buildPage` 原先按未去重的条数判断一页
  是否读满，提前停止后去重只剩二十几条，并报告"没有更早的记录"，页面只显示最近一轮。现在按去重后的条数判断。
- **从 NexBot 发到桌面会话的消息**（`items.ts`、`inbox.ts`）：Claude Code 把收件箱消息记为 `isMeta` 的
  `origin.kind: "peer"` 记录，原先被跳过。现在由 NexBot 发出的显示为用户本人的消息，停止显示为提示；发出的说明缩成一行，
  旧版说明仍可识别。桌面版附在用户消息里、整块都是 `<system-reminder>` 的文本块不再显示。
- **上下文窗口**（`context-usage.ts`、`claude-desktop.ts`）：桌面版会话记录里的模型带 `[1m]`（会话记录文件里没有），
  据此按 100 万计算；通用的 `autoCompactWindow` 是压缩阈值，不再优先于 1M 模型。为该模型单独设置的窗口仍然优先。
- **网页**：运行中输入框为空时只显示停止，有内容时只显示发送；新建会话的「工作树」改为 Worktree 勾选框，勾选即新建
  工作树，分支名可点开修改；侧栏会话图标不再平时置灰；工具卡片里长命令不再把状态挤出卡片。
- **Mac / iPhone**：Worktree 勾选框、停止/发送单按钮同步。

## 限制

- 没有在真实的 Claude 桌面会话上端到端操作网页验收（分页、远程消息、上下文窗口用本机真实记录在代码层面核对）。
- 只有桌面版自己的会话记录带模型的 `[1m]` 后缀；由 NexAgent 或终端启动、且没有为该模型单独设置窗口的 1M 会话，
  仍按通用 `autoCompactWindow` 或其后的规则推断。
- 运行中输入框有草稿时只显示发送，要停止需先清空输入框。
- 电脑端修复需要那台电脑的客户端升级到 Windows 0.9.43 或 Mac 0.2.35；均未在实体手机上安装测试。
