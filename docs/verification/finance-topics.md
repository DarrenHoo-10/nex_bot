# Finance assistant and independent conversations

The paired Stock gateway contract is described in the [finance assistant integration plan](../plans/2026-11-09-finance-assistant.md). In the Stock checkout, `tests/test_finance_cross_service.py` starts real loopback Core and Stock services with temporary SQLite databases and synthetic identity, model, quote and Feishu boundaries. Set `NEXBOT_TEST_CHECKOUT` to this checkout to run it. The user-system integration checkout exercises both users' private business writes. The public-data checkout also runs the cross-channel conversation case.

The service verifies Stock browser credentials at each use. In a bound workspace native requests, streamed updates and tasks also verify the current user-center session. Accepted finance tasks can renew their own binding after the original browser credential expires. Public report subscriptions have a separate, revocable public-only feed with its own cursor. The channel controls in Feishu settings use the selected app and a versioned transition through the paused state. The settings were exercised in headless Chrome through transfer and rollback with local fixtures. An app's physical workspace owner can transfer it.

The Stock management link uses `?settings=feishu`. Headless Chrome opened the production Web build from that link, signed in against synthetic identity responses and landed on the visible Feishu card in Settings → Connectors. Opening the link issued no Feishu write requests.

`GET /api/agents/finance` resolves `{botId}` through a stable `finance_assistant` role binding scoped to workspace and owner. New assistants start in full permission mode. Name edits do not alter the role binding.

`POST /api/agents/input` accepts `botId`, `text`, `clientId` and either `newConversation: true` or `conversationId`. Optional `sourceContext` and `audience` (`private` by default) are immutable topic metadata. The response is `{taskId, conversationId, messageId, queued}`; queued input has a null task ID until it starts. The complete request participates in idempotency: changing text, destination, source or audience under the same client ID fails. Legacy clients without topic options retain their continuous conversation and steering semantics.

`GET /api/agents/topics?bot=…` returns `{topics}`. Each topic includes title, audience, source context, activity time, logical message count, unread count, latest messages and active task. `GET /api/agents/messages?bot=…&conversationId=…` uses the existing messages/streaming/sync response. `POST /api/agents/read` accepts `conversationId` plus sequence. `POST /api/agents/cancel` stops only that conversation and cancels its pending inputs.

Inputs are durably queued in `agent_topic_inputs`, FIFO within a conversation. Separate conversations obtain separate tasks and runtime sessions. Recovery resumes pending inputs; completed effects are not replayed as a new request. Retrying an uncertain HTTP response retains its original client ID. `POST /api/agents/edit` replaces only a not-yet-started queued message, preserves its old receipt and publishes a replacement. `POST /api/agents/retry` restarts a failed/cancelled task only when its tool ledger contains no potentially executed business effect; unknown/executed effects require explicit reconciliation and a new instruction. `GET /api/agents/tasks?bot=…&conversationId=…` returns scoped task and effect history.

Published callbacks carry the exact message, task and conversation identity. Public tasks omit global memory, recall, other conversations, background reports and device data; their private tools and generic connectors fail closed. They can search their own transcript/projection and invoke the authorized `stock-finance` connector, whose gateway must enforce the public audience independently. Private independent conversations keep automatic global history and recall out of their prompt, while explicit tools retain the assistant’s authorized private/shared memory, skill and device capabilities. Full mode affects approvals; it does not bypass explicit tool grants or public audience restrictions. Background jobs and delegated child conversations inherit the root topic through `agent_topic_children`, including public tool restrictions. Job message/stop/list and briefing sources stay inside that topic. Child reports publish back to the exact root. Private topics can explicitly query authorized private/shared memory and historical references; public topics may search only their own root history. Public connector lists expose only the enabled authorized financial connector identity with a generic public label; live public tools are discovered through the gateway. Job listings, cached receipts and resumed tool-result projections are recomputed in the root topic scope.

The NexBot Web transcript includes one compact entry per independent finance topic. Opening an entry uses the shared message renderer and composer with a conversation-scoped feed, reply, read and stop. Starting a message from the main chat creates a private topic. Stock Web exposes the same conversation IDs in its session sidebar. Other assistants preserve their existing UI. Source context is displayed as the destination, never as a security credential.
