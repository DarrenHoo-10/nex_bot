## 线上数据预演

在 prepare 阶段，对另一组独立的 `VACUUM INTO` 副本运行 `release/deployment-user-topics/preview.mjs`：

- 预演使用随机密钥，存储的凭据无法解密；进程内禁用了 `fetch`，不会发出模型、embedding 或 rerank 请求。
- 只执行确定性的整理步骤：升级、继承、档案归属、进入容器、合并、解散。
- 报告只包含计数、哈希和长度，不包含记忆内容。副本用完即删。

| 项 | 结果 |
|---|---|
| 账号库 | 6 个，其中只有主账号库有主题（5 个助手、34 个主题） |
| 迁移前后可见范围 | 每个助手的核心记忆渲染与 34 个查询的召回结果完全一致 |
| 升级为用户主题 | 2 个（同一个助手），访问范围只有原助手 |
| 满足复现条件的叶主题 | 0 个：现有记忆都在最近 14 天内，自动建容器的条件还不满足 |
| 容器 | 0 个 |
| 档案归属 | 6 份 |
| 向量 | 单个助手最多 29 个，读取全部向量 0.2 ms，远低于 2000 个的缓存门槛 |
| 段落档案 | 3 份，其中 2 份超过 3000 字 |

上线后对生产库只读核对：`promote` 记录 2 条，用户主题 2 个，每个只有原助手作为负责者；没有容器，所有助手的记忆步骤都没有错误，与预演一致。

## 结论与限制

- 现有数据量很小，阈值（3 天、14 天、0.7、0.6、2000 个向量）都还无法用线上数据校准。建议上线两到三周后再统计一次：容器数、`revert` 占比、转交次数和召回耗时。
- 超过 3000 字的段落档案占比是 2/3，高于第三阶段 5% 的门槛，但样本只有 3 份，暂不据此启动分块。
- 授权、转交和记忆隔离只在测试与隔离实例中验证过，没有向生产会话发送测试消息。
- 预演和部署脚本在已忽略的 `release/deployment-user-topics/` 目录里。
