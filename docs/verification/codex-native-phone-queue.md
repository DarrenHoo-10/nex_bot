# Codex 手机发送：原生队列的发布验收

本项验证的是手机在聊天输入框中点击「发送」，不是在远程终端里打字。对支持外部队列的受管 Codex CLI（稳定版 0.172.0 起，并核对运行版本及命令能力），设备调用同一可执行文件的 `queue` 命令，以所属 `CODEX_HOME` 和原生 thread UUID 投递普通文本，不传 `--resume`。`nativeQueued: true` 是 Codex 队列接受回执；不是用户消息已出现在转录、模型已开始推理或回复已经完成。原生队列在目标线程可以执行时取件，真正的审批仍需处理。旧运行时保留原有路径；终端斜杠命令和对运行中轮次的显式引导不走普通跟进队列。

## 发布前验收门槛（不是通过记录）

只在隔离 Core、独立用户配置、独立工作目录和测试终端中进行。必须使用待发布安装包里的设备执行器及真实、兼容的 Codex CLI；手机可连接隔离 Core，模型端用仅监听回环地址的测试服务。不要复制个人配置、凭据、MCP、hooks、生产数据库或真实会话。

1. 像现有安装一样先启动一个已命名的 `--no-daemon` 终端，完成一轮，留下不同于下一条手机消息的电脑草稿。只重启设备执行器，保留原终端及 thread ID；至少一例使用无新版启动标签的旧终端。另测新建空会话的首条消息。
2. 在测试手机发送一条唯一文本，不在终端按任何键。核对返回为已入原生队列、未宣称已开始；**在同一 thread 的新增转录中看到这条用户消息恰好一次、测试模型的回复也回到手机**。检查原始电脑草稿未被覆盖或提交。再在 Codex 警告详情页打开时重复，保持面板打开；还需覆盖中文、多行文本，以及手机文本与原草稿恰好相同的情况。
3. 在未交还 HTTP 回执时重放相同请求 ID：不得二次入队，已保存的队列回执仍可读。注入设备侧队列命令已执行但回执丢失，必须显示结果待确认，不能再粘贴、补回车或另建写入者。更换线程、配置目录或断开设备后，旧目标不能收到新消息。

`codex-native-queue.test.ts`、`bridge.test.ts`、`workbench.test.ts` 及各客户端的回执用例覆盖上述边界的不同层级。仅通过模拟用例、看见队列回执或核对安装包摘要，均不能替代第 2 步的收发往返。
