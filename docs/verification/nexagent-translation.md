# NexAgent 会话翻译

在「设置 → 模型 → 翻译服务」从已连接并启用的供应商模型中选择一个。选择后自动保存，译文使用该供应商已有的连接和密钥。选择 MiniMax M3.1 Flash 时使用低思考强度。关闭翻译后，客户端展示原文。工作区从未设置过翻译服务时，网页保留已有的浏览器本地翻译。

设置对当前工作区生效。工作区数据库通过迁移 57 创建设置表，只保存供应商 ID、模型 ID 和版本。每次翻译都验证该连接仍可用。切换模型、变更连接或关闭翻译时，旧请求的结果不再返回给客户端。

Core 只在助手回复完成后翻译正文。模型收到经占位符保护的段落，代码块、日志行和表格保留原样。超过长度上限或不在 Core 最近文本缓存内的回复继续显示原文。

## Jev 正文判定

在 Core 的运行环境中设置 `TYPESAFE_API_KEY` 和 `NEX_TRANSLATION_JEV_CORE_ID` 可为一个工作区启用 Jev。后者填写该工作区数据库 `workspaces` 表的 `core_id`。将密钥保存在服务端的私有配置中。缺少任一配置或 ID 不匹配时，Core 使用原有筛选规则。

通过 `NEX_TRANSLATION_JEV_PROXY` 可指定只用于 Jev 的 HTTP(S) 代理，例如 `http://127.0.0.1:7897`。留空时直连。

判定在回复完成后的独立翻译请求中异步执行。客户端立即显示原文，会话发送和流式输出照常进行。该工作区的候选段落会在移除受保护内容后发送给 TypeSafe。纯中文、代码块、日志和表格在本地跳过。`jev-1.14.0` 对每段给出包含可读英文正文的概率，达到 0.7 的段落交给已配置的翻译供应商。低于阈值保留原样。

每条回复的 Jev 判定总预算为 5 秒。超时、请求失败或答案无效时立即按原有规则筛选，翻译照常继续。每个 Core 进程共享失败计数，第 11 次失败后停用 Jev 一小时。期满自动恢复判定，失败次数重新累计。降级期间的规则译文与 Jev 译文分开复用。

在隔离 Core 中挂起 Jev 请求后，会话仍返回原文并接受下一条消息。Mac Air 上的代理联调仅使用合成段落。每种输入测量三次，单段中位数为 1.40 秒，六段合批为 1.69 秒，均不含后续翻译。用接入代码经代理判定六段另测一次，用时 1.47 秒。

## 验证记录

- 隔离 Core、替身设备和 loopback 供应商通过真实认证和翻译接口。覆盖工作区隔离、选择和关闭、无权限请求、过期版本、停用模型、并发去重、保护内容和切换供应商。
- 打包网页在独立浏览器夹具中通过 8 项检查。验证了设置页选模型、重新进入保留选择、关闭及重新启用、复用已有密钥进行翻译和切换原文。
- TypeScript、lint、Core 和网页构建通过。6 个相关测试文件共 187 项通过。
- macOS Debug 应用和独立 iOS 模拟器目标构建通过。Apple 端交互未在模拟器中运行。
- 模型响应由夹具生成。实际 MiniMax 账户可用性、译文质量与耗时待用脱敏样例测量。
