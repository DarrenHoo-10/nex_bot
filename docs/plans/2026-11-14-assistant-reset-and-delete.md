# 助手列表操作：重置记忆与删除助手

更新于 2026-11-15。助手列表提供重置和删除。两个操作共用持久化删除任务。

## 1. 用户操作

| 助手行的位置 | 内容与行为 |
| --- | --- |
| 第一行 | 左侧为助手名称，右端原时间位置为常显的横向三点按钮「…」。无消息或未选中的助手也可操作。 |
| 第二行 | 左侧为单行消息预览或工作状态，超长截断；时间靠右、不压缩，保留原来的日期格式。没有时间则留空。保留未读标记。 |
| 点击行主体 | 打开该助手；点击「…」只展开对应助手的菜单，保持当前对话、输入草稿和滚动位置。 |
| 菜单 | 依次显示「重置记忆」「删除助手」，删除项用危险色。菜单以该行的按钮为锚点，靠近底边向上展开。 |

行主体和菜单按钮是同级控件，不能嵌套两个按钮。菜单按钮的读屏名称为「{助手名}的操作」。支持触摸、Tab、Enter、Escape 和点外关闭。取消后焦点回到原按钮；删除后移到相邻行或「创建助手」。桌面仅头像的折叠栏保留原有导航，展开列表后显示操作入口。

选择菜单项后显示确认框，目标绑定不可变的助手 ID。标题使用助手名，影响数量取 Core 的预览结果；获取失败时可重试。文案示例：

- **重置「研究助手」的记忆？** 将清空该助手的 6 个会话和全部私有记忆。重置后无法查看旧聊天，共享记忆仍可用。按钮为「取消」「重置记忆」。
- **永久删除「研究助手」？** 将删除该助手的 6 个会话和 2 条定时规则，3 项工作区待办将取消指派。此操作无法撤销。按钮为「取消」「删除助手」。

重置当前助手后打开其新对话；重置其他助手时停留在当前对话。删除当前助手后选中列表中相邻的助手，删除最后一个后显示现有空列表。取消、断网、预览过期均不得乐观移除列表项。

## 2. 数据归属与清理边界

| 数据 | 重置记忆 | 删除助手 |
| --- | --- | --- |
| 身份、角色指令、模型与权限配置 | 创建新 ID，沿用名称、头像、角色指令、模型、工具权限及连接配置 | 清除专属配置、角色指令和绑定，保留工作区模型连接、设备及其凭据 |
| 私有记忆 | 清空手动文档及其历史版本、自动事实与主题、私有核心记忆、综合结果、检索索引与缓存 | 同重置 |
| 聊天、附件、工作记录 | 清空旧会话、消息、摘要和专属聊天附件引用，从空白对话开始；保留工作状态和结果记录时，清除其中引用的旧聊天正文、预览和跳转入口。附件最后一个引用消失后才回收文件 | 移除其专属消息、摘要、附件关联、工具参数与输出、工作记录。附件最后一个引用消失后才清理文件和受管远端对象 |
| 待办、定时规则 | 保留用户填写的任务和规则；下次执行读取规则本身，从新上下文开始 | 移除专属例行规则和待触发实例；保留工作区待办及用户填写的内容，解除指派和指向已删除执行记录的引用 |
| 共享数据 | 保留工作区文档、共享核心记忆、用户主题和原有访问权 | 保留共享正文及其他助手访问权；去除已删助手的授权与维护职责；唯一维护者被删时标记为待分配，不扩大可见范围 |

以业务所有权决定清理范围。例如用户主题存在 `assistant_memories` 中，创建者的 `bot_id` 可以正好是被删助手，归属应以 `assistant_topics.owner='user'` 判定。删除创建者时保留共享条目的稳定 ID 与其他助手的引用，解除指向已删除私有原文的来源链接。不得按创建者批量删除整张表，也不得用空关键词调用现有的 `MemoryPrivacy.preview`：该接口会遍历共享文档和跨助手依赖，语义不同。

删除范围为当前 Core 管理的在线数据。外部聊天平台、用户自行导出的文件、既有备份按各自保留策略处理。其他助手和用户已经保存的独立副本按其自身归属处理。操作日志仅保留操作 ID、助手 ID、计数、时间和状态，不记录被清除的正文。

## 3. Core 接口与执行顺序

现有 `POST /api/bots/archive` 会拒绝有未结束任务的助手、标记归档并停用例行任务。本次复用登录校验、任务检查和版本冲突处理方式，另加生命周期服务。建议接口如下。

| 请求 | 输入与结果 |
| --- | --- |
| `POST /api/bots/lifecycle/preview` | 输入 `botId, action`，action 为 `reset_memory` 或 `delete`。返回目标名称、影响计数、阻塞项、短期有效的 `previewId`。预览不写业务数据。 |
| `POST /api/bots/lifecycle/execute` | 输入 `previewId, requestId`。Core 重新校验所有者与范围，接受后返回 `202 {operationId, status, replacementId}`。同一请求重发返回原操作；同一 requestId 搭配另一份预览返回 409。 |
| `GET /api/bots/lifecycle/operations/{operationId}` | 返回 `cleaning / completed / needs_retry` 和新助手 ID（删除时为空）。断线重连或重复提交均可找回结果；清理器按持久化进度继续执行。 |

三个接口仅向当前工作区的所有者会话开放，校验服务端的工作区和用户身份；不暴露为模型工具。预览绑定用户、工作区、助手、动作、版本及影响对象集合的摘要。影响记录变更时由数据库触发器递增该助手的范围版本。确认时比较版本并复查进行中的工作，避免再次枚举聊天记录。未经登录返回 401；已登录但无权查看目标时统一返回 404。

1. **检查活动工作。** 两种操作如有进行中、等待批准或外部执行结果未核实的工作，均返回阻塞项。界面允许查看并停止相关任务，经用户核实后重新预览。已排期但尚未开始的规则按上表处理。内部记忆维护由 Core 取消，不要求用户手动停止。
2. **原子接受。** Core 在同一事务内写入删除任务，标记旧助手已删除，更新待办及同步版本。重置还会创建新助手、复制设置、接续定时规则及待执行实例，并把新 ID 写回操作记录。任何一步失败都回滚。成功后旧聊天立即无法查看，副本的收件箱、运行会话和私有记忆库从空白开始。重复提交原请求会得到同一个副本。
3. **立即消费。** 提交后唤醒本地清理器。每批处理至多 256 条消息或 24 个历史任务，附件、私有记忆、段落档案和运行会话也分批处理。每批单独提交，批间交还事件循环。附件远端对象的待删清单与本地解绑一同提交，远端记忆库通过回收清单处理。
4. **重试与恢复。** Core 启动时以及每 15 秒扫描未完成任务，读取已提交的阶段和游标。失败批次回滚，进入重试等待。远端清理失败保持待处理，所有清单完成后操作才返回 completed。

## 4. 多端同步

正在查看被重置助手的客户端用 replaces_id 找到副本，清空旧消息、草稿和投递队列。旧助手 ID 永久失效，离线请求和旧链接无法访问副本。在线设备通过原有同步事件刷新；离线设备要等恢复连接并同步才能获知这次变更。

## 5. 实施顺序与验收

1. **Core 数据层。** 在 [服务入口](../../server/personal-os/index.ts) 新增路由，在 [助手服务](../../server/personal-os/agents.ts) 旁实现预览、版本屏障、操作日志与清理器。实施前逐表列出归属、引用关系和回收方式，重点走查 [记忆维护](../../server/personal-os/assistant-memory.ts)、[主题权限](../../server/personal-os/topic-access.ts)、[私有与共享核心记忆](../../server/personal-os/core-memory.ts)、待办执行引用、附件和全文/向量索引。
2. **客户端。** 在 [共享 Web 列表](../../src/personal/components/ContactSidebar.tsx)、[Mac 列表](../../apps/apple/NexBotMac/ContactsList.swift) 和 [iOS 列表](../../apps/apple/NexBotiOS/ContactsView.swift) 实现同一布局及确认流程。Web、Windows 与采用共享界面的 Android 验证各自窗口尺寸和输入方式。由 Core 声明是否支持生命周期操作；新客户端连接旧 Core 时保留原列表，不展示不可执行的菜单。
3. **隔离验收。** 按[仓库验证约定](../verification/README.md)启动临时 Core，使用两个助手、两个客户端和合成数据。以下均为待执行的验收用例。

| 场景 | 通过条件 |
| --- | --- |
| 编辑 A 的草稿时点 B 的「…」 | 菜单和确认框都指向 B；取消、重置 B 或删除 B 均保留 A 的选择和草稿。窄屏长名称、长预览、未读数和时间互不覆盖 |
| 重置 A | A 打开为空白对话。用户无法通过历史列表、搜索、导出、工作记录或旧链接找回预置的聊天标记；旧消息直链返回 404。模型提示、记忆检索、原文 ID 和任务回忆均不含该标记。共享标记仍按原权限可见，新消息能形成新的记忆 |
| 第二台设备停留在 A 的旧聊天 | 在线时收到失效通知即清空旧正文，迟到分页响应不能回填；离线设备恢复连接后，先同步再渲染。返回键、旧搜索结果和消息引用均不能重新打开旧聊天，B 的会话仍可查看 |
| 重置与旧任务竞态 | 在提取请求和摘要生成期间重置；放行迟到响应，再重启 Core、重建索引，旧标记仍检索不到；离线端的旧消息不能自动投递 |
| 删除 A | A 的私有记录、索引、独占文件和定时触发均不可用；A 创建的用户主题、B 的权限、共享文件与工作区待办仍在。旧链接不可访问，删除最后一个助手后可创建新助手 |
| 双端并发与越权 | 新任务出现或受影响范围变化使旧预览失效；双击、超时重试只产生一个操作；另一工作区不能预览、执行或查看结果 |
| 中断与恢复 | 分别在接受事务后、文件清理中和完成通知前模拟崩溃；恢复后状态可查询、操作可收敛，未完成不报成功。另一个助手在整个过程中可正常使用 |

验收记录应同时保存用户可见结果、模型实际收到的上下文和清理后的数据检查结果。只验证列表项消失不足以证明记忆或专属数据已清除。
