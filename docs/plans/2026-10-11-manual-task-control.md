# 任务不限累计用量与用户停止

2026-10-11 用户决定：任务不设累计上限，用户自行终止。本文优先于此前方案中的 Task Token、模型次数、工具次数、运行时长预算和 AdjustTaskBudget 命令设计。

## 执行规则

用户目标及其 A2A 子任务不设累计 Token、模型请求次数、工具调用次数或任务运行时长上限。任务内 memory.reflect 的模型请求遵循同一规则，不占后台自动整理的每日额度。每个实际模型请求仍保留 ModelInvocation / MemoryModelInvocation 归属、状态、真实 usage 与缓存输入记账；未知用量不记为免费，也不自动重试副作用。

模型上下文容量、单次输出长度、网络故障超时、设备执行租约、审批有效期和并发 worker 数量属于单次协议/资源约束，不是 Task 累计预算。A2A 的既有祖先循环检查与三层路由结构约束保留，取消此前单根任务最多八次求助的总次数限制。无人值守的后台记忆整理保留独立每日维护额度，不能限制用户正在执行的任务。

## 用户停止与事务边界

Agent 消息输入框旁持续显示“停止任务”，审批或等待同伴时同样可用。停止选中 Agent 当前未结束的工作，Core 在一个事务中将目标及所有未结束的 A2A 后代设为 cancelling，提升 run_generation，撤销待批/已批决定，丢弃未消费输入、取消未完成模型 invoice 和 A2A 链接，然后终止 Pi worker、终止对应的记忆模型请求，并向 Device Node 发送取消命令。其他独立 Agent 的工作保持独立。

Node 取消帧包含 callId 与原 argumentHash，在当前绑定内核对不可变日志，不能借取消创建新调用。终端只终止本次调用拥有的进程树，返回带 cancelled 的持久失败回执；电脑输入中断仍可能已经产生效果，保留 unknown，不声称撤销，也不重放。Core 未收到设备回执时同样保留 unknown；设备重连后重新传递已取消任务的停止指令并对账。停止后的迟到结果可以完成设备证据记录，不能把 Task 重新排队或提交 Agent 回答。

已完成的操作与记忆保留。停止不等于回滚。重启发现持久 cancelling 时直接完成 cancelled 并清空 AgentInbox 的 active_task_id，不启动该任务或后代的新模型请求。用户之后发新消息建立新的任务。

## Schema v9

既有 schema v1 文件及 checksum 不变，通过 task-control-schema.sql 增量迁移，将 tasks 的四个旧限制字段改名为 legacy_max_model_calls、legacy_max_tool_calls、legacy_token_budget、legacy_deadline_at。旧值仅用于历史兼容，不参与授权、调度或预算判断。新 Task 使用满足旧 NOT NULL / CHECK 的最小兼容占位值，不用巨大有限值冒充无限额度。迁移保留原任务、调用、记忆与外键；Core 构建必须携带新迁移文件。

## 验收

真实 Pi SDK 与合成模型执行超过 400,000 Token、24 次模型请求、40 次工具调用且旧截止时间已过的任务，验证自然完成和用量账本。隔离 Node 执行长命令后通过 Core Stop 终止，核对错误摘要不能取消、正确摘要取消、持久回执、没有后续输出与重启后无再次执行。另验证停止 A2A 子树、恢复持久停止屏障、停止前台记忆模型请求以及中断原生输入保持 unknown。桌面 fixture 必须点击消息输入框旁的实际停止按钮并看到等待动画结束；所有变更验证使用临时配置与合成数据。
