# 主设备识别、Windows computer use 与通用技能

Agent 是用户创建的长期联系人，不设默认 Agent，不按名字或职业选择实现。

## 设备事实与权限

主 Core 启动时自动注册自己的 Device Node，稳定 device_id 与设备令牌分别保存在 Core 表和加密 vault。主设备默认提供系统元信息、终端和已安装的电脑操作，不设终端/屏幕授权开关。文件共享目录仍由用户选择；不选目录不会影响终端或电脑操作。登录凭证不能代替设备令牌。原来已配置的外部 Node 连接保留，不擅自改绑。

`device.inventory` 在 Core 返回实时在线设备目录；`device.info(deviceId)` 经 DCP 获取目标节点实际 hostname、系统版本、架构、安装能力和本机授权。系统版本不等于硬件型号，未知型号不编造。主机与客户端分别标注，不把 Core 系统当成客户端系统。

目录区分 online、supported、granted。模型请求末端刷新目录和身份，历史中的「没有设备/不能操作」不能覆盖最新事实。目录不表示可读取任意文件。文件 path 相对用户在目标机器选择的目录，终端未选共享目录时使用当前用户主目录作为 cwd；cwd 不是访问范围沙箱。普通操作直接执行，危险或无法确定影响的具体操作才批准。

migration 7 已交付设备信息、文件读取、computer use 和技能入口；其规则与 checksum 保持不变。migration 8 为未编辑的上版默认策略增加 device.exec，新 Agent 默认具有所有通用工具。主设备启动时自动刷新默认能力，客户端在已有配对上同样刷新，不改变 device_id 或令牌。审计中出现用户策略修改的实例原样保留，需要用户在工具权限中自行启用新能力。

## Windows computer use

Windows x64 发行版随包提供 CUA Driver SDK 0.28.2、对应 native DLL/N-API 和开源声明，复用项目已有依赖，不依赖 Codex/ChatGPT 插件、额外安装的 CLI 或共享 daemon。运行在目标 Device Node，首次调用才初始化，退出时 orderly shutdown。

电脑操作是默认能力，主设备和已配对客户端均不弹额外启用确认，也不要求保存能力开关。远程设备仍须完成设备配对，登录凭证不能代替设备令牌。截图会进入用户配置的模型，需要支持图片的模型。未安装执行器或离线时如实说明，不提示用户打开不存在的开关。

Broker `device.computer(deviceId,operation,parameters)`：

- `tools` 返回实际 Native SDK schema。
- `list_apps/list_windows/get_window_state` 自动执行。
- `bring_to_front/click/type_text/press_key/scroll/drag` 普通操作自动执行。删除、覆盖重要文件、发送消息、付款、交易、安装软件和修改安全设置等最终操作由 Agent 在 broker 顶层标记 risk="dangerous" 和 riskReason，在实际执行 Agent 的联系人中批准。

仅接受观察过的明确窗口 pid/window_id；观察两分钟有效，动作后必须重新观察。优先后台输入；只有执行器明确返回 background_unavailable，才允许重新观察后使用前台输入；前台模式本身不代表危险操作。不自动重试副作用。不接受全局桌面输入、任意 session/连接、截图文件输出、剪贴板、脚本、kill_app 或浏览器凭证接管。不能操作本进程及父 NexBot 进程窗口来批准自己或修改本机权限。

结果复用 DCP 原始 canonical envelope、调用摘要、本机策略版本、租约、持久日志、ack 和恢复协议。Native 输入中断/完成未知进入 unknown；目标设备人工核对前不会重放。改变本机授权使旧批准失效；单纯 Core 端口变化/同配置保存不改变权限版本。

截图以 Pi 工具 image content 发送给视觉模型，不塞进 JSON 文本，恢复投影也采用同一转换。限制窗口图像与可访问性树大小。图像只进入已有本地工具/Pi记录，不显式复制进长期记忆。

本次桌面 computer use 只交付 Windows。macOS/Linux 的系统识别、已有文件与终端通道保留；原生电脑操作另行接入各平台授权和执行器，不能由 Windows 验收推断。

## 具体操作的风险与批准

终端只自动放行静态、已知的观察命令，如 Get-Location、Get-ChildItem、Get-Content、whoami。命令组合、重定向、变量/命令展开、脚本、未知可执行程序及其他影响不确定的命令先批准，risk="standard" 不能绕过此检查。以后扩展自动命令范围须配套验证，不能用关键字黑名单声称覆盖任意 shell。

GUI 普通操作默认自动执行；危险效果由 Agent 结合任务意图和最新窗口内容标记，Core 对风险标记、参数摘要、Agent/本机策略版本和批准记录核验。相同 click/Enter 在不同页面可能分别是翻页和付款，因此操作名不能独立判断危险性。这是可信个人 Agent 的执行约定，不是对任意模型或恶意内容的完整安全沙箱。不可依赖模型风险标记拦截所有危险 GUI，已有窗口范围、防自审批、观察时效和 unknown 不重放约束仍保持。

恢复时旧版尚未执行的静态只读终端查询可以取消旧的冗余审批，复用原调用 ID 执行一次。旧版 GUI 输入没有风险标记，不能把等待批准的点击/按键默默当作普通操作；保留审批，不自动执行。已拒绝、已取消和结果未知的操作不因默认配置升级重放。

A2A 始终自动，无需批准。记忆删除/遗忘仍在执行 Agent 的联系人中批准。读取共享目录的设置按钮仅保存文件目录，不能作为终端/电脑能力的开启步骤。

## 内置技能

先内置五项第一方、通用、无脚本技能：设备识别、电脑窗口操作、记忆维护、同伴协作、定时汇报。`skill.list/skill.read(skillId)` 按当前 Agent 工具策略过滤，从固定随包文件读说明；skillId 不能成为任意路径。

技能是流程知识，不是权限。执行仍需 Broker、设备配对、Agent 工具策略和具体危险动作审批。不开放第三方技能自动下载、脚本自动运行或默认联系人。后续可添加文件整理、网页资料收集、文档处理，前提是先完成真实执行工具和针对性验证。

## 验收

业务 fixture 覆盖默认无 Agent、主机元信息与重启稳定 ID、默认终端不依赖共享目录、用户修改的策略不扩权、技能读取、截图图像送达模型、普通输入无需批准、危险输入批准前不执行及拒绝不执行、修改授权使旧批准失效。

`scripts/smoke-personal-computer.mjs` 启动独立合成 Electron 窗口，原生发现该 HWND，截取该窗口，经真实 DCP/Pi 传给合成视觉接口，验证普通 Unicode 输入无需批准，再验证显式危险输入批准前不执行，最后读取合成文本框验证。拒绝后台输入后的前台操作另需观察。所有数据和输入目标均为临时 fixture，不针对用户真实应用。

Windows 验收使用随包 Electron 的 Node 模式，与 Core EXE 的 DPI manifest 一致；不能以普通 node.exe 的虚拟化坐标冒充桌面环境。150% 缩放下另校验 PNG 实际尺寸与窗口物理边界，确认完整窗口而非局部截图。独立 Windows Node CLI 的原生屏幕操作不在这次交付的验收范围。
