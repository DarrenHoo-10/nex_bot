# Personal Agent 产品与领域修正

用户在 2026-10-11 明确纠正：交付目标是多个独立、长期存在的个人 Agent 联系人，可以直接与任意 Agent 沟通。0.2.x 的“新对话 / 最近对话”产品入口偏离该目标。本文件优先于之前设计中以 Conversation 为用户入口的部分；既有权限、Pi 隔离、设备执行和恢复约束继续适用。

后续记忆与协作以 [主设备记忆与协作方案](2026-10-11-personal-agent-memory-hindsight.md) 为准：真正的 Hindsight 运行在主设备；所有 Bot 读取公开职责与能力目录；同一工作空间 A2A 自动通信；只有危险工具操作在实际执行 Agent 的消息流里申请批准。0.3.3 尚未实现这些新增行为。

Agent 是统一的领域实体，没有系统固定的职业类型。首次启动没有默认 Agent，由用户显式创建；名字、可选身份说明、能力与记忆都是实例数据，不能据此硬编码不同执行流程。以下契约更新 0.3.3 的预置联系人行为，不自动删除已有安装的数据。

## 产品契约

- 全新工作空间的联系人列表为空，显示“创建 Agent”入口；没有可用 Agent 时不提供默认聊天对象，不生成任务或调用模型。启动、重启、重连、升级和归档最后一个联系人不自动创建 Agent；既有联系人保留。
- 左侧是 Agent 联系人：身份、最近消息、未读和工作状态。点击联系人进入同一个持续消息流；没有“新对话”或会话列表。
- 右侧是当前 Agent 的资料、私有 / 共享记忆、任务和例行任务。设备是 Agent 可调用的资源，不与 Agent 身份绑定。
- Agent 生命周期独立于模型上下文与任务。创建 / 更名 / 改身份不清空消息或记忆；任务完成、停止和 Core 重启不创建新的 Agent。
- 名字也是身份的一部分，名字必填，补充身份 / 职责 / 沟通方式选填，空白归一为 `""`。更名或调整身份沿用 bot_id，并通过版本检查避免覆盖并发编辑；执行中也能编辑，工具权限和审批仍按原策略。
- 所有 Agent 复用统一的创建、执行、检索与协作规则；用户显式创建时写入同一基础策略，设备及外部工具另行授权。名字不选择职业模板、专用提示词、bank 或路由分支；模型可以结合名字与当前资料理解身份及求助对象。
- 同一工作空间内的 Agent 读取最新公开目录（id、名字、补充身份摘要、专长、可用能力摘要、状态和版本），不直接检索同伴私有消息和记忆。每次实际模型请求前从 Core 读取最新资料，包括工具 / 审批后的继续执行；闲置 Agent 在下次执行时获取。改资料不产生通知、消息、模型调用或额外任务，已发出的模型请求按当时快照完成。目录中的身份与职责描述可为空，不能由名字推导执行权限。
- 用户发消息、例行任务到期、其他 Agent 委派是不同的唤醒来源。闲置时不循环调用模型。关闭窗口进入托盘，明确退出才停止 Core；开机启动由用户选择。
- 协作请求及结果显示在参与 Agent 的消息流中，自动传播问题、最少必要背景和回答；不逐次批准内部 A2A，不附上父 Agent 的全部私有历史。子任务执行上下文不出现在联系人列表。接收方读取自己的私有 bank 与共享 bank，按自己的策略和资源授权执行；危险操作由接收方在自己的消息流申请批准，发起方提供等待状态和跳转入口。
- A2A 在发起方显示轻量居中的“已发消息给 / 消息来自”提示，带联系人头像和名字，不单独展示同伴返回的全文；正常用户答复仍由当前 Agent 展示。在接收方，来信仅显示“消息来自”提示，不展示任务正文或“展开任务”入口。成功回复归属于接收方 Agent 自己，正文默认收起，折叠栏显示“已回复给 {同伴名字} · 展开”，展开后可收起。流式生成时显示“正在回复给 {同伴名字}”，不能提前宣称已回复。失败和取消仍显示实际状态说明，不冒充成功答复。
- 旧系统回复记录通过只读投影转换为正确署名的回复；保留原消息 ID、序号、内容和 A2A 结果回执，不发送重复消息。折叠是显示状态，不删除数据，也不影响 Agent 获取完整工具结果。

## 领域与存储

| 对象 | 归属与作用 | 约束 |
|---|---|---|
| Agent / Bot | 用户显式创建的统一持久助手实体 | 复用 bots 主键、身份、策略与记忆范围；无职业枚举或种子实例 |
| AgentInbox | Agent 的唯一用户通信入口 | bot_id 主键；保存读取位置及当前交互任务 |
| AgentMessage | 用户、Agent、同伴及系统的可追溯消息 | Agent 内递增序号；source_key 唯一，结果重放不重复发布 |
| AgentInputReceipt | 向 Agent 发送消息的接收回执 | (bot_id, client_message_id) 唯一；内容冲突拒绝 |
| AgentTaskLink | Agent 收件箱与后台 Task 的关系 | 记录 owner / routine 来源；一个当前交互任务，后续输入补充该任务 |
| ExecutionContext / Conversation | 某个任务的内部工作上下文 | 新目标创建上下文，恢复沿用原上下文；不是产品导航对象 |
| AgentJournal | Agent 已完成工作的私有记录 | task_id 唯一，明确标识为历史执行结果；不冒充用户事实 |
| AgentRoutine | 用户授予 Agent 的例行职责 | 一次、间隔或每日；版本控制、暂停、预算沿用 Task |
| RoutineOccurrence | 某次计划触发的持久回执 | (routine_id, scheduled_at) 唯一，原子绑定 Task；重启不重复派发 |

Core 继续模块化单体，业务数据使用 core.db，新增表使用增量迁移。Agents 模块独占收件箱、消息、回执和工作记录写入；Routines 模块独占例行任务与触发记录。Execution 通过回调发布已提交的工作结果，这些 Core 记录共享同一个事务边界。后续主设备上的 Hindsight 使用自己的 PostgreSQL，由 outbox 和 MemoryAdapter 接入，不与 Core 假设共享事务。runtime.db 仍只是 Pi 上下文投影。

## 输入、执行与记忆

新的公开输入命令按 bot_id 接收，不要求用户选择 conversation_id。接收回执、消息、上下文及任务关联在同一事务中提交。当前交互任务未结束时输入遵循原补充 / steering / 审批失效规则；取消仍是独立操作。新目标使用新的内部上下文，并加载该 Agent 最近的消息、完成记录和私有 / 显式共享记忆。

消息历史自动持久化，完成记录自动保存且注明来源。长期事实仍使用现有 MemoryDocument、版本和写入授权；任务输出不会自动变成可信的用户偏好。历史检索仅限当前 Agent 的消息，其他 Agent 的私有资料不进入上下文。任务切换与上下文压缩不删除收件箱历史。

以上记忆装载与写入描述截至 0.3.3 的已交付行为。后续见 [主设备记忆与协作方案](2026-10-11-personal-agent-memory-hindsight.md)：普通私有记忆写入和整理自动完成，范围、版本、来源与预算仍检查；任意 Agent 直接检索自己的 bank 与共享 bank，证据不足时根据公开目录自动向合适同伴求助。同伴回答保留转述来源，不自动成为用户确认事实。检索与求助规则不依赖预设名字或固定职责。

既有非委派对话消息导入各自 Agent 收件箱，原记录与 ID 保留。旧任务、审批和 SDK 恢复绑定不改写。迁移后旧未结束用户任务绑定当前交互任务；同一 Agent 存在多条旧活动任务时保留全部，并阻止开启新任务绕过它们。

## 例行任务与常驻

用户明确创建例行任务即允许按该计划调用模型；工具权限仍经 Broker，后续风险策略仅为危险操作请求批准，普通私有记忆整理与内部 A2A 自动执行。到期发生与任务创建分开持久化。Agent 正在处理任务或等待审批时，新例行任务排队，不补充旧任务，也不绕过审批。暂停后取消尚未派发的触发；已运行任务通过停止任务操作取消。

Core 离线期间不会执行任务。恢复后每项计划最多补一条到期发生记录，后续计划推进至未来，避免补跑大量模型请求。每日计划使用保存的 IANA 时区，并处理夏令时重复分钟。闲置轮询只读数据库，不调用模型。

## 验收

1. 切换联系人、完成不同目标及重启后，身份、消息、读取位置和记忆保持连续。
2. 同一发送 ID 重试仍是同一消息与 Task；新的目标有独立内部上下文，并能参考已有工作记录。
3. 委派请求和结果出现在对应联系人中；无子会话导航，无父私有记忆泄漏。
4. 例行任务在无需新用户消息时唤醒 Agent，结果进入其消息流；重启与重复 tick 不重复执行。
5. 暂停、等待审批和已有任务不会被例行任务绕过；窗口隐藏时 Core 保持工作，明确退出后安全关闭。
6. 用隔离 Core / Electron profile 验收后打包、升级本机应用。个人数据库与密钥不进入仓库或安装包。
7. 任意 Agent 只检索自身与共享 bank，按公开目录自动咨询合适同伴；无 A2A 批准框。危险操作只有实际执行方联系人展示批准框，发起方能跳转查看。
8. 干净安装为零 Agent；用户显式创建、归档最后一个联系人及重启后，不出现自动补建。升级保留既有联系人与历史。
9. 使用任意名字、空身份说明或修改名字，均走同一创建与执行流程；权限不按名字分配，bank 仍按稳定 ID 绑定。单个 Agent 也可独立工作，无隐藏协调者或专家依赖。
