# Agent 模式：在任何设备上查看、继续和接手电脑上的编程 Agent

状态：设计已确认，2026-11-15 定下四项决定（见第 12 节），尚待实现。技术方案见 [2026-11-15-agent-mode-implementation.md](../plans/2026-11-15-agent-mode-implementation.md)。

参考：

- [nwverse/persona](https://github.com/nwverse/persona)（MIT）：会话识别、单写入方、钩子、助手监督的做法和实测结论。
- [herdr-core](https://github.com/herdrdev/herdr-core)（Apache-2.0）：终端运行时。
- [Paseo](https://github.com/getpaseo/paseo)：导入并继续其他应用里的会话。

本文与 [10-07 固定运行时方案](../plans/2026-10-07-personal-ai-os-identity-and-devices.md) 的关系：该方案中的“不安装、不登录外部 Agent CLI”和“不扫描用户主目录”只约束**助手模式**。Agent 模式是另一种模式，可以接外部 CLI，但只读取第 5 节列出的会话目录。

## 1. 问题

- 用户在电脑上用 Claude Code 和 Codex 写代码。一离开电脑，就看不到进展、不能回答 Agent 的提问，也没法让它接着做。
- 本机近两周的会话几乎都在桌面应用里，不在终端：Claude 的 71 个会话全部来自 Claude 桌面应用，Codex 的 25 个全部来自 Codex 桌面应用。所以“识别会话”不能只看终端。
- nex_bot 已经通过设备执行器连上用户的电脑，但设备调用一次只能跑一个，最长 20 秒，而且只能一问一答，承载不了长时间运行的会话。

## 2. 目标与不做的事

**目标**

- 列出每台电脑上的 Claude Code 和 Codex 会话，包括 nex_bot 终端里的、用户自己终端或桌面应用里的、以及已经结束的。
- 在网页上实时操作真终端。回到电脑前，可以接着用同一个进程。
- 已停止的会话可以在 nex_bot 终端里用同一个会话 ID 继续。
- 在指定电脑的指定目录里新建会话。
- 之后再做：结构化的审批卡；由助手派活、监督和分叉；更多客户端；nex_bot 终端之外的会话也能接收消息。

**不做的事**

- Core 不运行外部 CLI，也不保存 CLI 的凭据。
- 不用无头模式，即 `claude -p`、`codex exec` 这类没有交互界面的运行方式。
- 同一会话不允许第二个进程同时写入，也就是不并行 resume。
- 不替用户安装、登录或升级 CLI。
- MVP 不做手机原生界面、Mac 电脑端，也不做与助手的协作。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| Agent 会话 | 一次 Claude Code 或 Codex 对话，以 CLI 自己的会话 ID 标识 |
| nex_bot 终端 | 由 nex_bot 启动、由内嵌 herdr-core 持有的终端，里面运行 CLI 的交互界面 |
| Agent 桥 | 设备执行器里新增的模块，负责发现会话、解析会话记录、管理终端和转发终端流 |
| 会话状态 | 运行中、等你处理、空闲、已停止 |
| `cli-agent` | 代码里的统一名称。现有代码中的 “Agent” 指助手联系人（`agents.ts`、`/api/agents/*`、`agent.*` 工具），新功能不能和它们混用 |

## 4. 总体结构

```
网页（MVP），以后加入其他客户端
        │ HTTP（列表、操作）+ WebSocket /api/cli-agents/stream（会话记录、终端流）
        ▼
Core：会话索引、记录缓存、操作记录、终端流中转、审计
        │ DCP 新增 cli.* 消息（JSON 控制消息 + 二进制终端帧），不走现有的设备调用
        ▼
电脑客户端的设备执行器（先做 Windows；Mac 共用同一份代码）
  ├─ Agent 桥
  └─ 内嵌 herdr-core：终端由它的 holder 进程持有，不随客户端退出而结束
        └─ claude / codex 的交互界面
```

- **电脑端**：会话记录和终端都在用户的电脑上。Agent 桥只读取会话目录，只在需要时把内容推给 Core。
- **Core**：Core 只中转和缓存，不保存终端输出。现有的实时更新（SSE 发 `change` 信号后，客户端重新拉取全部状态）不适合高频数据，所以会话记录和终端流走单独的 WebSocket。
- **网页**：一个入口，两种视图：「终端」和「对话」。

## 5. 会话从哪里来

| 来源 | 怎么识别 | 能做什么 |
| --- | --- | --- |
| nex_bot 终端里的 Claude / Codex | herdr-core 终端标签，加上启动时指定的会话 ID | 实时终端、对话、发消息、中断 |
| 用户自己终端里的 Claude CLI | `~/.claude/sessions/<pid>.json`，`entrypoint: cli` | 运行时只能看对话；停止后可以在 nex_bot 终端里继续 |
| Claude 桌面应用 | 同一个文件，`entrypoint: claude-desktop*` | 同上 |
| Claude 后台会话（`claude --bg`） | 同一个文件 | 同上 |
| 用户自己终端里的 Codex CLI | `~/.codex/sessions/**/rollout-*.jsonl`，`originator` 为 CLI | 同上 |
| Codex 桌面应用 | rollout 中 `originator: Codex Desktop`；部分会话的记录只在应用的 SQLite 数据库里 | 有 rollout 的会话同上；只存在数据库里的会话放到第 4 期 |

- 会话记录的原件始终在电脑上，Core 只缓存有限的一部分。
- Claude 的会话文件格式没有公开文档。解析时要容错：遇到不认识的记录类型直接跳过；每个 CLI 版本各留一份测试样本。

## 6. 真终端

- **为什么选 herdr-core**：
  - 它是 herdr 背后的终端运行时，本身不画界面，官方说明可以“从你自己的应用里使用”。
  - 许可证与 nex_bot 相同，都是 Apache-2.0。
  - 0.1.21 版的 Windows 压缩包 3.9 MB，里面已包含 ConPTY。
  - 客户端协议有文档，是 JSON-RPC。
  - 终端由 holder 进程持有，nex_bot 客户端重启或更新时终端照常运行。
- **独立运行**：nex_bot 用自己的会话名（`HC_SESSION`）和通信端点运行 herdr-core，不影响用户自己装的 herdr 或 herdr-core。
- **多人同时查看**：
  - 网页默认只看；点“操作”后才能输入。
  - 终端尺寸由最近一次操作的查看端决定。
  - 电脑前有人正在输入时，远程发来的消息会等他输完。
- **在电脑前接着用**：网页上点“在电脑上打开”，电脑上会弹出一个终端窗口并接入同一个终端；也可以直接在终端里运行 herdr-core 的 attach 命令。
- **Persona 没做的部分**：Persona 没有给 herdr-core 做实时终端，Windows 上的实时终端也没做。所以这部分要我们自己实现，并在第 0 期实测。

## 7. 用户操作与会话状态

| 会话状态 | 对话 | 终端 | 发消息 / 继续 |
| --- | --- | --- | --- |
| 在 nex_bot 终端里运行 | 实时 | 实时，可以操作 | 可以发送，也可以中断 |
| 已停止（任何来源） | 历史记录 | 无 | “继续”：在新的 nex_bot 终端里，用原目录、原配置目录接着跑同一会话 |
| 在用户自己的终端或桌面应用里运行 | 实时 | 无 | 不能发；停止后可以继续。Claude 的收件箱发送放到第 4 期 |

- **继续之前先检查有没有别的写入方**：
  - Claude 本身不阻止两个进程写同一个会话，所以必须查 `sessions/*.json` 里是否有活进程持有这个会话。
  - Codex 会拒绝在已有写入方的情况下 resume，可以作为最后一道保护；nex_bot 继续前仍要先检查。
- **继续时不会带上的设置**：会话中“本次允许”过的审批，以及 Claude 的部分开关。

## 8. 等你处理

- **MVP**：
  - Claude 根据会话文件里的 `status: waiting` 判断会话在等人。
  - 列表和页面上显示“等你处理”。网页打开期间，用浏览器通知提醒，点开就是终端。
  - Core 目前没有推送服务，所以页面关闭时收不到提醒。
  - Codex 不会把审批请求写进会话记录，所以 Codex 的等待信号要在第 0 期找到。找到之前，Codex 会话只显示“运行中”。
- **第 2 期**：
  - Claude 会话启动时，用 `--plugin-dir` 注入 nex_bot 钩子，只作用于这个会话，不改用户的全局设置。审批请求和提问会变成卡片，手机上就能回答。
  - 如果在终端里先回答了，卡片会自动撤回。30 分钟内没人回答，就交还给终端处理。

## 9. 与助手模式的协作（第 2 期）

1. **助手派活给 Agent**：在用户授权的电脑和目录里新建会话，结果回到助手话题。
2. **助手监督 Agent 会话**：
   - 每轮结束后判断会话处于“在做”“在等某个前提”还是“做完了”。
   - 能自动处理的情况：临时错误后继续（最多 5 次）、额度重置后继续、定时唤醒、把需要用户决定的事做成卡片。
   - 这些开关默认关闭，因为每次自动处理都要花用户的 token。
3. **分叉成助手话题**：把会话摘要导入一个新的助手话题，由 Pi 助手接着做，原会话不动。

安全边界照搬 Persona：

- 推代码、部署、给别人发消息、合并、删除、花钱、动生产环境，都要用户明确批准。
- 每次自动动作之前重读会话；用户正在电脑上操作时，不做任何自动动作。
- 接手由用户本人发起，助手的工具不能触发。

## 10. 安全

- **远程终端等于远程 shell**，Claude 的 `!` 命令可以直接运行命令。为此：
  - 只有已登录的本人可以打开可操作的终端。
  - WebSocket 校验 Cookie、Host 和 Origin。
  - 每次接管终端、新建、继续、发送和中断都写入审计日志。
  - 本机控制暂停时，所有远程终端转为只看。
- **herdr-core 的接口没有鉴权**，同一系统用户下的程序都能连上。Agent 桥不对外暴露它，只转发指定的终端方法，而且只启动 `claude` 和 `codex`。
- **读取范围**：只读会话目录。不读 `.credentials.json`、`auth.json`、`*.key`，也不读配置文件里的密钥。会话列表只上传元数据，对话内容按需读取。Core 缓存的记录加密保存，并且有容量上限。
- **开关**：Agent 会话跟随本机控制，登录后自动开启。“暂停控制”会停止推送、拒绝新操作，但不结束任何终端。设备设置里可以单独关闭 Agent 会话。

## 11. 客户端

- **网页**：新增入口，层级为电脑 → 项目目录 → 会话。会话页提供终端和对话两个视图、输入框，以及新建、继续、中断、在电脑上打开等按钮。
- **Windows 客户端**：它用的是打包在安装包里的界面，不从 Core 加载界面。MVP 只发布电脑端能力（herdr-core 和 Agent 桥），以及设备设置里的“Agent 会话”开关。客户端界面里先隐藏 Agent 入口。
- **Android、Mac / iOS、Mac 电脑端**：放到第 3 期。

AGENTS.md 要求界面改动在同一任务里同步到 Apple 端。MVP 不同步，因为 2026-11-15 已决定 MVP 只做网页，Apple 版放到第 3 期。

## 12. 已确认的决定（2026-11-15）

1. **两种模式**：助手模式与 Agent 模式是两回事，Agent 模式可以接外部 CLI。
2. **真终端**：Agent 以 CLI 的交互界面运行，电脑前和远程操作的是同一个进程。不采用无头模式。
3. **终端运行时**：内嵌 herdr-core。
4. **MVP 范围**：先做网页版，电脑端先做 Windows。

**待确认**：现有界面把助手叫作 Agent（“我的 Agent”“添加 Agent”），新入口如何命名还没定。建议把现有的改回“助手”，与 README 和“助手模式”的说法一致，新入口叫“Agent”。在这之前，新入口暂用“Agent 会话”。
